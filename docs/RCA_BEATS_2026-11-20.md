## The detector (src2/drumclash.py, DRUMCLASH=1, off by default)
- **What it measures.** Each deck's own drum onsets (kick <150 Hz plus snare 150 Hz-2 kHz flux, 5.8 ms frames, 2-bar windows) are placed exactly where the engine plays them, then cross-correlated over ±half a beat.
- **Score.** The share of drum-on-drum bars that agree on **one confident non-zero offset**: |lag| > 25 ms, peak ≥ 0.2, and the peak beats the zero-lag correlation by ≥ 0.1, with lags within ±15 ms of each other.
- **What it ignores.** Weak or wandering peaks don't count. In the pro calibration they're as common in pro blends as in ours, so they aren't evidence of a train wreck.
- **Calibration (pro p95 only).** 30 of 33 pro overlaps were located (3 decks not locatable). Pro scores run 0 to 0.268, so **pro p95 = 0.212** is the flag line (`rca_beats/detector_calibration.json`).
- **Pick time (protrans/recreate.py).** For every family's window it runs `window_eval`, which also simulates the lock fallback and judges the residual. A flagged window gets **+DRUMCLASH_W × (1 + score)**, with W = 5. That's larger than every other pick term combined. When all families are flagged, it nominates the cheapest unflagged natural window from the engine candidates as `clash_alt`.
- **Render time (src2/finephase.py `lock_fallback`, runs inside BLEND_LOCK).** This happens when the kick+snare lock gives up ("inconsistent / too few agreeing bars") or under-corrects. If the detector's offset cluster is confident, the incoming is moved by that offset, and the move is undone if it doesn't reduce the clash. The residual verdict goes in `trans[i]['drumclash']`.
- **Hard check (recreate.py).** A pick whose rendered decks are still flagged gets replaced by the next-cheapest unflagged family, which is re-rendered.

## Detector v3 (DRUMCLASH=1, off by default): two terms, each gated at the pro p95 (14:00 ET)
Both terms run on rendered decks: each deck on its own, real fader, after BLEND_LOCK. Only HPSS-percussive content counts.
- **Lattice term** (`drumclash.lattice_eval`). It catches a constant flam or hits landing off the beat.
  - The reference deck is the one with drums up in more bars. Per bar, it measures the strength-weighted share of the other deck's audible hits that sit more than 25 ms off the reference deck's 16th lattice.
  - Calibration (`rca_beats/drumclash_calib3.py` -> `detector_calibration_v3.json`): 31 pros, 734 bars. BAR_OFF = 0.677 (per-bar p95) and FLAG3 = 0.307 (pair p95). Pro max 0.5.
- **Pulse term** (`drumclash._pulse_rows`). It catches one deck's straight beat against the other's free roll.
  - On drum-on-drum bars it takes |1-beat autocorrelation of A's percussive onsets - B's|.
  - Calibration (`rca_beats/drumclash_calib4.py` -> `detector_calibration_pulse.json`): 31 pros, 607 bars. PULSE_BAR = 0.528 and PULSE_FLAG = 0.273. Pro max 0.5.
- **Combined verdict:** the worse of the two terms. clean = at or below FLAG (pro p95); gray = above FLAG, up to HIGH 0.5; clash = above 0.5, a majority of bars.
- **Pros:** none clash. Gray: lattice hm08 (0.5) and js13 (0.364); pulse maduk03 (0.286) and pola00 (0.5), so 4/31 are gray. Netsky15 and maduk05 can't be measured: deck A isn't in the pro clip (r 0.043 / none).
- **Labels:**
  - hm09 B: pulse 0.6, clash. Lattice 0.125, clean.
  - WAO->GB B (no lock): lattice 0.75, clash (flam about -36 ms). Pulse 0.364, gray.
  - hm13 B: clean on both. Partial pulse loss early (gaps 0.29-0.45, below the 0.528 bar threshold), so not detectable at pro-p95 confidence.
  - JS12 default A: clean on both. It is an "other fault" (slowdown / half-time placement), not a flam.
- **Where it acts** (`recreate.py`, `finephase.lock_fallback`):
  - Pick time uses only the pulse term, from per-track caches (st/<id>.pulse.json). Levels are unity, so it's an upper bound, and the penalty is mild only (0.1 x confidence). The pick-time lattice check was dropped: on st audio without the fader it read hm09's breakdown exit as a clash.
  - After render, a clash is a veto. The engine renders the next-cheapest scored families, then up to 2 natural windows from cs that pick time reads clean (for example, fading over a breakdown), with at most 4 extra renders; the first clean render wins.
  - A lattice clash first tries moving the incoming deck by the measured flam, and keeps the move only if it helps. A pulse clash can't be fixed by moving a deck.
  - A gray render is listed for an A/B and never re-picked.
- **Smoke test,** hm09 before the thresholds were set (`rca-dcsmoke-1120`): the default nat_short rendered as a pulse clash (0.6) and was replaced by nat_long ['n',208,None,32,32].
