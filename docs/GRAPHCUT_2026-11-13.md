# Graph-cut crossfade eval, 13 November 2026 (ET)

Prototype of Robinson & Brown (ISMIR 2019 LBD, [arXiv:2301.13380](https://arxiv.org/abs/2301.13380))
as `FADE=graphcut` (off by default; sticky `GRAPH_CUT=1` so a family env cannot overwrite the renderer).
Planning still uses the long-blend window (`_longish()`). The engine applies a bar-quantized
6-band STFT seam (20–80, 80–250, 250–800, 800–2500, 2500–7000, 7000–20000 Hz) instead of the
Butterworth low/high lanes and the master xfader. Mid seams live on `d['graphcut']` so they
do not invent an X1-illegal `auto` key.

This write-up exists because graphcut did **not** match or beat the current default on the
like-for-like pair score, so no blind A/B was cut. Defaults and thresholds were not changed:
`protrans/rules.json` still has `FADE=long`, `linger_pen_w=0.15`, and `GAP_DB` is still 9.84.

## Why the dip improved but is not gone, and why the score still lost

The 44.5 dB summed-lows dip is mostly a window problem, not a same-time fader problem.
Listen has essentially no bass in this 16-bar outro-over-intro (incoming <250 Hz sits 9–20 dB
under the outgoing groove for the whole window).

Early graph-cut attempts kept a hard complementary bass swap (required by X1 at crossfader
x 0.2–0.65, 1–4 bars). Combined with bass-never-doubles, that turned outgoing lows off
before Listen could cover them, and the dip got *worse* (46.4 dB). Pushing the swap as late
as X1 allows ([214, 218]) did not help: the hole is Listen having no bass, not the swap
being a bar early.

The root-cause fix: if incoming never covers (outgoing body minus incoming > `GAP_DB/2`
for the whole window), do not write a hard `auto['low']` swap. Outgoing and incoming bass
ride the equal-power xfader in the graphcut gains, and incoming bass reaches unity at the
window end so the post-blend drop is not muted. Mid/high may still have their own seams.
On this pair, `incoming_covers_bass=False`, `bass_follow_fader=True`. Mid/high seams also
landed on the same late bar (all six seams at 9), so the per-band freedom barely showed.

That shrinks the dip **44.5 → 28.9 dB** (15.6 dB better) because mid-window lows stay
healthier while Final Hours still rides the fader. The metric still sees a deep min at the
end of the fade, when the outgoing groove is gone and Listen still has no bass — so the dip
is not gone. Filling it would need a longer window that includes Listen's bass, or a
later-than-X1 handoff; neither was done (X1 and `GAP_DB` were left alone).

pro-similarity dropped **43.1 → 39.61**, so this is a loss on the stated "match or beat"
rule. The dip improvement plus passing tests is not enough to count as a win or to cut A/B clips.
